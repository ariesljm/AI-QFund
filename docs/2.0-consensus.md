## 0. 一句话定位

把 1.x 的「LLM 选赛道 → 赛道内排序」的**行业轮动建议器**，重写为「全市场量化初筛 → LLM 定性排雷」的**基金推荐系统**；
进化机制从「参数寻优」换成「知识积累 + 校准」，因为项目自身的实证证明前者在本项目的样本量下不成立。

## 2. 决策清单

### Q1–Q2 重构形态与边界

**Q1 决策**：**推倒重写**（用户否决了"原地演进"）。
**Q2 决策**：**决策层重写，管道层扩写。**

| 层 | 处置 |
|---|---|
| `app/engine/*`、`app/model.py`、`app/features/calculator.py`、`app/domain.py` | **重写** |
| `app/data/*`、`app/repo/*`、`app/utils/*`、`app/web/*` | **保留，按需扩展** |

**理由**：数据基座的复杂度不来自设计，来自外部世界的脏（编码、停更、除权、公告日、交易历对齐），这些坑被 910 条测试与 11.5M 行存量数据钉住。2.0 对数据基座没有架构级要求，只有**扩写**需求。
**代价**：删除会发生在主干上（`sector_pool` / R2-R4 / `ga` / `insights` / `style_track`）。

---

### Q3–Q4 同类分组与基金池

**Q3 决策**：**同类 = RBSA 第一行业（持仓聚合口径）；赛道不再作为推荐漏斗**，仅保留为标签口径。
**Q4 决策**：**池子 = 主动权益（混合型 + 股票型，剔指数型）；同类组 `n ≥ 10` 才进训练样本与候选池；不做回退。**
**Q19 决策**：RBSA 用**持仓聚合**，不用净值回归反推。

**理由**：
1. 2.0 的 label 要求减掉"同类基准平均收益"，必须定义"同类"；而 2.0 又把"赛道池"从漏斗里拿掉了——赛道因此降级为**标签口径**而非漏斗层。
2. 数据支持"不回退"：`n<10` 只涉及 **201 只基金（1.7%）**，直接剔除的代价可忽略。
3. 净值回归反推的**权重** `weight_1` 用于**分组**的证据是负的（Q4−Q1 胜率差 −20.6%，"胜率随 weight_1 单调递增：否"）。按 Q8 的标准，无证据的算法不进生产。
   - ⚠️ **修订**：同一报告里反推**拟合优度 `r2`** 用于**特征**的证据是**正的**（Q4−Q1 = **+21.9%** 单调；多元回归已控动量，coef **+0.045, p=1.05e−13**），但模型级（A3）**未复现**增益。两者是不同的东西：被否决的是“反推权重做分组”，**不是**“反推一致性做特征”。详见未决 #9。
4. 对"同类分组"这个用途，RBSA 的 15~45 天滞后**不是致命缺陷**——行业 beta 是慢变量。1.x 的错在于拿滞后 RBSA 去做及时的事（R2/R3），不在 RBSA 本身。

**代价**：指数基金（3,881 只）本次不做。用户已明确"可以在项目里单独推荐指数型基金，使用相同的逻辑"——**排在主动权益链路之后**，唯一例外是"同类"对指数型不成立（应为跟踪指数），届时另定。

### Q5 硬过滤口径

**决策**：文档 §2.1 的「基金经理任职当前产品时长 < 6 个月 → 剔除」改为「**基金净值历史长度 < 6 个月 → 剔除**」。

**理由**：这条过滤的真实目的是"别让模型学一条太短的业绩序列"，短序列的问题在**净值历史长度**，不在谁在管。且 1.x 的 Step 2 已有"停更/短历史打标"，可复用，零新增数据源。
**代价**：无。留后门——将来补了经理数据，可升级为"净值短 **或** 经理新上任"的并集。

### Q6–Q7 频率与 LLM 触发

**Q6 决策**：**保持日频推荐**（否决文档的"周五 20:00 初筛 + 21:00 审计"）。
**Q7 决策**：**日频打分 + 事件驱动审计**——LLM 只在两种时刻被调用：基金**新进 Top30**，或该基金**已披露持仓/公告发生变化**。审计结果必须带**失效条件**（持仓期次 + 重仓股集合 + 风险事件版本）。

**理由**：
1. Top30 由 20 日动量、估值分位这类**日频变化极小**的特征产生 → 相邻交易日高度重叠。日频全量审计＝每天对几乎同一批基金问同样的问题，然后**用它去重排 Top5**，每天换一只，理由是噪声。
2. 钱的成本不是主要约束（默认 `gpt-4o-mini`）；**信号冗余**才是。
3. LLM 的真实成本在**新增数据源**：2.0 §3.1 的"重仓股风险雷达"与"舆情争议"需要**个股粒度**公告/舆情检索，而现有能力只有东财宏观财经新闻 + 板块资金流，**零个股粒度**。

**代价**：审计缓存若写错失效条件，会把昨天的结论喂给今天已变的基金。这是本方案唯一容易写错的地方，必须有测试守。

### Q8 文档数值的权威性

**决策**：**文档数值即 v1 初值**，进配置表 + 标定报告，其后由进化闭环修正。**禁止硬编码在引擎里。**

**理由**：用户在"结构 vs 数值"上选择先落地、后修正。
**代价**：文档的 λ=1.5~2.0 没有任何证据支撑，且与生产值 1.0（= 标定报告结论）冲突。
**例外**：**λ 不采用文档值**——ticket 09 取 **1.0**。两个理由：① 1.0 是唯一有标定证据的值；② 改 λ 就改标签、改模型，**破坏与 1.x 参照曲线的可比性**，而那条曲线是 Q12 明确要保留的哨兵。文档的 1.5~2.0 记为待验证假设进标定报告（含 >1.0 区间，即标定从未测过的方向）。

### Q9–Q11、Q14 进化引擎（本共识改动最大的部分）

**Q9 决策**：**删除 GA（两个）与 LLM 元分析/洞察库**，按 2.0 §5 重建。
**额外理由**：1.x 洞察库的**消费者已经作废**——它回流到"选赛道 / 终选"prompt，而那两个 LLM 角色在 2.0 里都不存在了；内容形态（教训条目）与 §5.2 要的 Bad-Case 也对不上。

**Q10–Q11、Q14 决策**：进化 = **知识层 + 校准层为主体，参数层冻结**。

> **核心命题：参数是"知识不足时的占位符"。进化的终点不是把参数调对，而是让知识的增长去取代参数的自由度。**
> 不知道"何时该惩罚回撤"时你只能设一个全局 λ；积累足够案例后，"这类情境该惩罚回撤"是**知识**，不是标量。

| 层 | 对象 | 频率 | 权限 | 依据 |
|---|---|---|---|---|
| **A 知识层** | Bad-Case **与 Good-Case**、情境判据 | 持续 | 只增 | 唯一能单调增长的资产 |
| **B 校准层** | 每路信号的历史命中率与样本量 | 持续 | **自动降权/停用** | 概念漂移 = 命中率下滑，自动暴露 |
| **C 模型层** | LightGBM（含特征集） | 季度 | 自动切换 | "一次替换 + 新数据驱动"，非连续寻优 |
| **D 参数层** | λ / 入场门槛 / 排序权重 / 护栏阈值 | — | **冻结，人工改** | 效应小于噪声，且风险来自自证循环 |

**C 层的闸门替换**：文档的"IR 高 15%"在 ±8pp 测量噪声下**不可辨识**，替换为
→ **≥3 个不重叠子区间（牛/熊/震荡）同向不劣 + 非重叠窗口显著性检验**。

**长期运行的四个失效模式与对策**：

| 失效模式 | 1.x 病历 | 对策 |
|---|---|---|
| 自证闭环（裁判即运动员） | GA fitness 就是验收主标尺 | **主标尺冻结 + 标尺版本号** |
| 静默退化 | 无任何机制 | 固定口径效果记账 + 校准命中率曲线 |
| 复杂度只增不减 | 2 个 GA / 6 道防线 / 12 特征 / 87 测试文件 | **信号与特征退役机制** |
| 概念漂移 | 无检测 | 校准层自动暴露 → 自动降权 |

**§5.3 修正**：文档「规则库只允许新增排雷否决场景，严禁放宽一票否决」**不能推广到信号/特征类**，否则系统只能变复杂、永远不能变简单。
→ **否决类单向增严（安全方向不可逆）；信号/特征类可退役（需校准数据支撑）。**

### Q11、Q14 标尺分职

**决策**：

| 角色 | 标尺 | 用途 |
|---|---|---|
| **主标尺（守门 / 验收）** | **超额收益期望**（推荐组合 40 日收益 − 同期同类 RBSA 行业均值） | 判断系统有没有本事、是否降级 |
| **过程标尺（诊断）** | **校准准确率**（自陈置信度 vs 实际命中率） | 系统自我认知是否准 |
| **用户口径（展示）** | 绝对赚钱胜率（>1% 占比） | 对外展示，**绝不作为进化 fitness** |

**理由**：绝对口径会把"牛市赚得多"误判为"系统变好了"。1.x 已经在吃这个苦头——`docs/backtest/model_walk_forward_40d.md` 的验证期是单边下跌段（整体胜率 36%、IC≈0），模型被判"区分度失效"，但那很可能只是 beta 拖累。
**守门为什么必须用期望**：一个"60% 胜率、期望 +0.5%"的系统扣掉申赎成本后**期望为负**——用胜率守门等于允许系统用高频小胜掩盖负期望。

### Q12–Q13 验收框架

**Q12 决策**：**基线不是 1.x，是真值本身**——推荐的基金未来是否真的赚钱。1.x 降级为**参照系 / 哨兵**（回答"新系统是否比老做法更差"），**不拥有否决权**。
**Q13 决策**：**双层验收**。

| 层 | 内容 | 性质 |
|---|---|---|
| **结构层** | 全市场直接选基 + 硬过滤可执行 + 理由可追溯 + 审计可解释 + 监控闭环 | **上线门槛**（做完即达成） |
| **效果层** | 超额收益期望 > 0；牛/熊/震荡三段同向；校准曲线健康 | **持续守门**（不达标触发进化/降级，不否决上线） |

**理由**：功能性验收单独用＝**没有标准**（无任何可失败判据）；效果性验收单独用＝**项目被永久卡住**（第一版不可能在全区间显著为正），且卡住期间**最缺的数据一点也攒不到**（`evolution_insights` 2 行、`recommend_log` 28 行）。
**代价**：接受"先上线、后证明"，以虚拟池无真实资金为前提。

---

### Q15 Point-in-Time 口径

**决策**：**公告日口径**（`fund_holdings` 加 `disclosure_date`，样本只允许 `disclosure_date <= d`）；**拿不到公告日则退化为「报告期 + 15 个工作日」的保守滞后**。

**理由**：公募季报报告期 3/31、法定披露截止 4/22——用报告期口径**最多看到 22 天后的信息**，对 40 日窗口等于 **55% 的前瞻期被污染**，且方向是"让回测更好看"。而 `docs/quant-overhaul-plan.md` §3 写的正是报告期口径（`report_date <= d`）。
**代价**：回填时必须一并抓取公告日。**这条必须在回填前定，否则要重爬十万级请求。** 退化方案是保守近似，不会让回测虚高。

---

### Q16 监控对象

**决策**：**监控对象 = 系统推荐**，不引入用户/持仓实体。**schema 留缝**：状态机作用于"跟踪对象"抽象，跟踪对象默认为推荐记录，另留一个可选关联实体。

**理由**：用户明确"这是给推荐系统，是否建仓由用户决定"。B（监控用户持仓）会让系统**失去自我审计能力**——用户可能不按推荐买，推荐效果无从归因，校准层失去分母。
**代价**：不做持仓录入与个性化预警（产品功能，非系统能力）。

---

### Q17 交付边界

**决策**：**四模块全做**（模块一初筛 + 模块二审计 + 模块三状态机 + 模块四进化）。

**代价**：这是最大范围、最大数据账单、最长首次可用时间。四模块全做意味着**没有中间可运行版本**——1.x 停跑 + 2.0 未完成期间存在数据空窗（这正是 Q13 把效果验收降为"持续守门"的原因）。

### Q18 决策域处置

**决策**：**清库重建**——决策域表全部 DROP 重建，1.x 记录随代码消失。
**附加保险（零成本）**：清之前把决策域表**导出为归档文件**（几 MB，非 871MB 整库），并打 tag `1.x-final`。

**理由**：决策域内容贫瘠到无法验证迁移正确性（`quality_metrics` 0、`purchase_restrictions` 0、`evolution_insights` 2）。而 `llm_audit` 的 1,024 条来自已废弃的 `cctv_sentiment`，剩下 55 条是"选赛道 / 终选"的 prompt——**那两个 LLM 角色在 2.0 里都被废除**，对 2.0 的排雷审计校准没有迁移价值。
**代价**：放弃 1.x 生产历史（16 个推荐日）。保留回滚点。

### Q21 分支与生产保护（由 Q1 的"边界"事实倒逼）

**决策**：**全部重构在 `2.0` 分支内完成，`main` 不动。**

**理由（事实倒逼，不是保险）**：`.github/workflows/ci.yml` 在 **push main 时自动构建并推送镜像**，`docker-compose.yml` 是 `pull_policy: always` + `restart: unless-stopped` + `ENABLE_SCHEDULER=true` + 持久化 data volume——**main 是一个自动部署到生产的分支**。在 main 上重构＝每次 push 都把半成品推到跑着定时任务的实例上，而它的 data volume 是持久化的：schema 一改就会崩，或者更糟——静默什么都不做。

**不需要改 CI**：只要不 push main，生产零影响。
**白拿的收益**：生产上的 1.x 继续跑，补上了 Q12 里被降级的“哨兵”角色，零成本。
**合并前必须准备**：服务器 DB 的备份与迁移脚本、回滚路径。

## 7. 本共识明确否决的提案（防止反复）

| 被否决 | 理由 |
|---|---|
| 原地演进 / 全仓库重写数据基座 | 数据基座的复杂度来自外部数据的脏，重写＝重踩所有坑 |
| "同类"小样本回退到基金类型 | 小样本直接剔除只损失 1.7%，回退会让模型照样学会追行业热度 |
| 周频推荐 | 会把监控拖成周频，废掉全部日频信号 |
| 日频全量 LLM 审计 | 信号冗余：Top30 日间高度重叠，花钱买噪声 |
| 分组的 IR 高 15% 自动切换阈值 | 在 ±8pp 测量噪声下不可辨识，不构成闸门 |
| 泛化 Champion-Challenger 到所有参数 | 会把"无闸门的自动改"换成"闸门被噪声穿透的自动改"，重蹈 GA 覆辙 |
| GA / 连续参数寻优 | 噪声 > 全部真实信号；已有 −28.7% 事故 |
| 净值回归反推的**权重**用于分组（Style Tracking） | 自家 walk-forward 否决：`weight_1` 分层 Q4−Q1 −20.6%，非单调（注：反推**拟合优度 r2** 的证据方向相反，但未被否决——见未决 #9） |
| 用绝对赚钱胜率作守门指标 | 混入 beta；且允许系统用高频小胜掩盖负期望 |
| 建用户/持仓实体 | 会让系统失去自我审计能力；属产品功能，非系统能力 |
| 报告期 PIT 口径 | 最多泄漏 22 天，污染 40 日窗口的 55% |
| 在 main 上重构 | main 会自动部署到生产，半成品会打到跑着定时任务的持久化实例上 |
| “先留着观察”式保守清理 | 删除可由 S0 全库备份回滚，保守保留只换来“复杂度只增不减” |
