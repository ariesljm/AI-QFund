# 智能进化公募基金推荐与监控系统 (AI-QFund)

本项目基于"原生 Python + 外部 API + 本地 SQLite"极简架构，彻底抛弃高资源消耗框架。系统定位于"每日信号推荐与虚拟追踪"，通过客观动能捕捉中期趋势，并由大语言模型（LLM）进行宏观排雷与逻辑印证。

---

## 1. 系统运行与调度架构

### 1.1 核心工作流（调度器单时间全流程）

`docker-compose` 内 `ENABLE_SCHEDULER=true` 开启调度器，每日 `SCHEDULER_HOUR:SCHEDULER_MINUTE`（默认 14:30）执行一次**全流程**（`app/pipeline.py`）：

| 阶段 | 说明 |
|------|------|
| 数据基座 | 基金列表（周更）、净值增量、宏观指数、重仓股+行业映射（7 天周期，失败自动重试） |
| 推荐引擎 | 前置门控（数据就绪才跑）→ LLM 选赛道 → LightGBM 赛道内排序 → LLM 定论 → 入库 |
| 监控引擎 | 对 HOLD 持仓盯盘：防线链（趋势/锚点/漂移/优势/模型/LLM 证伪）→ 信号入库 |
| 进化引擎 | 每日结算度量（满 20 日窗口即结算）+ 月度重量活（GA 寻优/元分析/置信度衰减） |

各槽位独立容错：数据基座/推荐失败不中断监控盯盘（持仓信号链连续）。

## 2. 数据基座与状态机模块 (`app/data/foundation.py`)

本模块提供所有底层纯客观特征，彻底屏蔽分红导致的净值断崖干扰。

### 2.1 核心数据获取规范

- **净值标准**：强制使用累计净值 (Cumulative NAV) 或复权净值 (Adjusted NAV)，绝不使用单位净值
- **增量更新**：建立本地 SQLite 历史数据池，每日仅增量 Fetch T-1 日数据，避免被东方财富等接口源封禁 IP

### 2.2 宏观大盘状态机 (Regime Switch)

提取"沪深 300 指数"或"万得全A"近 60 日均线 (MA60) 状态：

| 状态 | 条件 | 特征权重偏向 |
|------|------|-------------|
| **BULL** (顺势环境) | 指数 > MA60 | 赫斯特指数 (Hurst)、向上捕获率、动量因子 |
| **BEAR** (防御/反弹环境) | 指数 < MA60 | 卡玛比率 (Calmar)、向下捕获率、乖离率 (BIAS，超跌反弹) |

### 2.3 量化特征工程 (X)

- **动态锚定 RBSA**：以最新季报十大重仓股为约束下限，滚动回归基金前三大隐形行业暴露度
- **动量与记忆特征**：60 日 Hurst 指数、近 20 日绝对动量
- **风险调整特征**：卡玛比率（区间年化收益/最大回撤）、区间下行波动率
- **资金面特征**：RBSA 第一大暴露行业对应的 ETF 近 5 日净申赎份额斜率

## 3. 推荐引擎 (`app/engine/recommend.py`)

采用"理科大脑（筛选）+ 文科大脑（否决）"的漏斗模型。

### 3.1 目标函数 (Model Target Y)

LightGBM 的预测目标是未来 20 日**绝对收益**（R1 目标切换后）：

```
Y = R_fund(t+20)
```

即未来 20 日绝对收益（非相对沪深 300 的超额收益）。推荐引擎全天候出手（不做预测分 > 0 硬过滤）；监控引擎据此判断持仓信号是否转负（预测收益 < 0 输出警惕）——推荐与监控共用同一门槛，避免「推荐看好、监控看空」的定义漂移。

### 3.2 LLM 顺位否决机制 (Sequential Veto)

将 LightGBM 打分前 10 名的基金及具体特征，喂给 LLM 执行一票否决。

**Prompt 模板结构：**

1. **【系统状态与规则】** 当前大盘状态、策略侧重、核心宪法（来自 `evolution_rules` 表）
2. **【今日宏观文本与资金流向】** 财经新闻摘要、领涨/领跌行业、ETF 净流入数据
3. **【候选名单 (按超额收益动能排序)】** 代码、真实重仓行业 (RBSA)、核心量化特征
4. **【任务指令】** 严格从第 1 名开始向下验证；若重仓行业符合宏观资金流向且无政策利空，立即选定并停止；若有明确利空或违背核心宪法，行使否决权并记录理由

## 4. 虚拟池监控引擎 (`app/engine/monitor.py`)

对所有尚未平仓的 HOLD 基金每日扫描，捕捉趋势破裂信号。**绝对不设固定 ROI 止盈。**

五道防线消费预装配快照（`DefenseContext`）逐道判定（详见 `CONTEXT.md`「信号」）：

| 防线 | 判定 |
|------|------|
| ① EMA60 趋势 | 净值趋势破裂（跌破 EMA60） |
| ② RBSA 风格漂移 | 最新 RBSA 第一大行业权重较买入时突降超 15pp |
| ③ 赛道锚点 | 持仓脱离推荐赛道（RBSA 第一行业不再命中锚定赛道） |
| ④ 板块优势 | 赛道相对优势转弱 |
| ⑤ 模型信号 | 模型预测信号转负 |
| LLM 逻辑证伪 | `buy_reason` + 最新新闻 → 逻辑链断裂（R4 报告期守卫：无新披露数据时跳过） |

输出持有(HOLD)/加仓(BUY_MORE)/警惕(WARNING)/离场(EXIT)四类信号，EXIT 即更新 `recommend_log.status`；净值陈旧（数据断裂）写独立 `is_stale` 告警，不参与信号升级链。

## 5. 进化引擎 (`app/engine/evolve.py`)

每日结算待定推荐（满 20 日窗口）+ 月度质量度量 + **LLM 教训沉淀**（`evolution_insights` 回流选赛道与定论提示词）+ **GA 排序权重寻优** + 置信度衰减 + 否决反事实监控；模型**每周重训**（训练与推理解耦：训练命中满 7 天触发，每日用已保存模型 + 最新特征打分）。

## 6. 技术栈

| 组件 | 选型 |
|------|------|
| 语言 | Python 3.11 |
| 包管理 | uv |
| 数据库 | SQLite (WAL 模式) |
| HTTP 客户端 | httpx（同步/异步统一；push2 域名 TLS 指纹伪装 + 三级降级） |
| 量化计算 | NumPy / LightGBM |
| LLM 接口 | OpenAI 兼容 API（base_url / api_key / model 见 config/settings.toml） |
| Web 框架 | FastAPI + Jinja2（单页仪表板，`app/web/`） |
| 前端 | 静态资源本地化（Tailwind 产物 + `app.js` 入库，零 Node / 零外网 CDN 依赖） |
| 调度 | Docker 内 daemon 线程定时全流程（`ENABLE_SCHEDULER=true`） / 手动 |

---

## 7. 架构约束

- **去中间件化**：原生 httpx 直连东方财富/天天基金 API，不用 AkShare 等重型库
- **正则提取**：HTML 表格用编译期正则匹配，避免 BeautifulSoup 等 DOM 解析器的内存开销

## 8. Web 展现层（只读单页仪表板）

面向个人投资者 / 策略研究者，日间只读展示系统每日产出的推荐、监控与进化结果，**无任何交易下单能力**。

### 页面 1：总览仪表板
- 大盘环境状态条：BULL（顺势）/ BEAR（防御/反弹）二态切换，附指数与 MA60 对比、乖离率。
- 今日运行概览：推荐日期、本日新推荐数、当前持仓数、今日平仓数。
- 今日推荐卡片：最新推荐的代码、名称、推荐日期、评分、所属环境、买入逻辑（LLM 自然语言）、RBSA 第一大重仓行业及权重。
- 候选 Top 10 漏斗：表格展示候选代码、名称、评分、重仓行业、是否被 LLM 否决及否决理由。
- 持仓虚拟池列表：每只基金当前累计净值、相对最高点回撤、状态（HOLD/EXIT）、平仓理由与日期。
- 宏观摘要卡：财经新闻摘要、领涨/领跌行业、ETF 净流入数据。

**页面 2：持仓监控详情**
- 基金详情滑出面板（追踪列表点击进入）：推荐**当日预测超额**（`recommend_log.score`，模型预测的未来 20 日收益分，UI 文案沿用「预测超额」）、**近 1 周 / 1 月 / 3 月 / 6 月涨跌幅**与同期沪深 300（`period_returns`）、推荐理由、前十大重仓、净值走势、最新监控信号。
- 单只基金累计净值走势（累计净值 vs 持仓期间最高点 `highest_nav`）。
- 防线链可视化：趋势 / RBSA 漂移 / 赛道锚点 / 板块优势 / 模型信号 / LLM 证伪（详见第 4 节）。
- 状态徽章：HOLD（持有）/ EXIT（已平仓）。

**页面 3：进化错题本**
- 规则列表：规则文本、来源亏损交易 ID、创建日期、是否启用（active）。
- 说明区：系统从错误交易中学到的硬规则（机制见第 5 节），作为次日 LLM 否决的"核心宪法"。

### 数据字段映射

| 用途 | 来源表 / 字段 |
|------|---------------|
| 大盘环境 | fund_features / recommend_log 的 `regime`、index_daily 指数与 `ma60`、fund_features `bias_60d` |
| 推荐与评分 | recommend_log（`score`、`buy_reason`、`status`） |
| 多周期涨跌幅 | `period_returns`（基金净值 1 周/1 月/3 月/6 月 + 同期沪深 300） |
| 持仓与回撤 | recommend_log（`highest_nav`、`sell_reason`、`exit_date`） |
| 量化特征 | fund_features（`hurst_60d`、`momentum_20d`、`calmar`、`rbsa_industry_1`、`rbsa_weight_1` 等） |
| 宏观信息 | macro_news（`news_summary`、`top_gainers`、`top_losers`、`etf_net_flow`） |
| 进化规则 | evolution_rules（`rule`、`active`、`source_trade_id`、`created_date`） |

### 交互与约束
- 纯只读展示，无表单提交、无交易操作。
- 手动触发管线 + 前端定时轮询只读 API（已实现）。
- 需提供空数据与有数据两种状态展示。
