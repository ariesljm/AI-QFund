# 标尺分职与主标尺冻结（Scorecards, Versioned）

架构决策：系统存在三种口径的"收益标尺"，用途各异、严禁混用；主标尺口径变更必须**人工批准 + 版本号**。

## 分职

| 标尺 | 口径 | 用途 | 属主 |
|---|---|---|---|
| **主标尺** | 相对同类的**超额收益**（同类 = RBSA 第一行业 + 全行业基金，样本 n≥10；`BENCHMARK_VERSION="excess_rbsa40d_v1"`） | 模型学习目标、结算账本的唯一聚合依据（绝对/超额 + 三统计量） | `app/benchmark.py` + `app/settlement.py` |
| **过程标尺** | 校准层的预测准确率/校准度 | C 层参数变更的机理来源，监测"系统是否越来越可信" | 校准层（票 18） |
| **用户口径** | 绝对胜率/绝对收益（>1% 为赚，`PROFIT_THRESHOLD`） | Web 展示与用户沟通，**不参与**排序/训练/结算聚合 | `app/domain.py` |

## 主标尺冻结

- 版本守卫：`settlement_ledger.benchmark_version` 与 `BENCHMARK_VERSION` 不一致时禁止聚合（旧记录不得与新标尺混算）。
- **口径变更 = 换版本号 + 人工批准**（如 benchmark 成分/窗口/同类定义变动），不允许就地覆盖历史语义。

## Considered Options

- **单一绝对收益标尺（沿用 1.x）** — 被拒：绝对收益混入大盘贝塔与赛道景气，40 日窗口下 55% 的样本被泄露污染（1.x 复盘：λ=1.0 标定下超额才是有效学习信号）。
- **无版本号的隐式口径** — 被拒：标尺口径是账本的"宪法"，改动不换版会让新旧结算数字静默不可比。

## Consequences

- 研究工具（walk_forward/backtest_model）的胜率口径与生产结算必须一致（`is_profit` 单一来源）。
- 历史证据（1.x 回测）与 2.0 结论严格区分：1.x 的数字基于绝对收益口径，不能直接与超额口径对齐。

## 冲突标注

与 ADR-0002（LLM 单接口）无冲突；与 ADR-0006（决策读缝）正交：读缝管"数据怎么读"，本 ADR 管"读出来后拿什么比"。
