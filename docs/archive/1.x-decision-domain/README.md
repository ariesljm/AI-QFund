# 1.x 决策域归档（赛道范式）

本目录是 **1.x 系统的行为证据留档**，不是设计文档。1.x 已被 2.0 取代；这里的表在 2.0 中会被 `DROP`，导出成文件是为了两件事：

1. **可回滚**：代码可以由 git 回到 `1.x-final`，数据库不能——`DROP TABLE` 不产生 diff。
2. **可追责**：1.x 究竟推荐过什么、为什么、事后如何，是判断"2.0 是否真的更好"的唯一原始材料。

导出脚本：`scripts/archive_decision_domain.py`（可重跑）。全库二进制备份见 `SERVER-BACKUP.md`。

## 1. 1.x 是什么

一句话：**LLM 选赛道 → 赛道内排序选一只代表基金 → 六道防线监控 → 遗传算法寻优参数**。

关键特征（决定了它为什么被替换）：

| 特征 | 后果 |
|---|---|
| 推荐单位是**行业赛道**，基金只是"该赛道的代表" | 用户拿到的是行业建议，不是基金建议 |
| 主指标是**绝对收益** | 混入市场 beta，分不清"系统变强"与"牛市来了" |
| 遗传算法直接以**赚钱胜率为适应度**寻优排序权重 | 用自己的验收标尺优化自己；详见 §4 |
| 风格跟踪用**净值回归反推**持仓 | 自家回测：反推权重分层胜率差 **−20.6%**、非单调 |
| 决策域落库跨度为 **2026-08-13 ~ 2026-09-12（约一个月）** | 全部"进化效果"证据来自单一行情段 |

## 3. 1.x 基线数字（**全部为绝对收益口径**）

> ⚠️ 下列数字的**口径各不相同、不可混用**。抄录时保留了各自的区间、样本与口径定义。这些是 2.0 的**参照系（哨兵）**，不拥有否决权。

### 3.1 阶段改造增益（`docs/quant-overhaul-plan.md` §2）

- 口径：同口径 walk-forward，区间 **2021-01 ~ 2026-08**，**67 个决策日**，赚钱口径 **决策日 r > 1%**
- 阶段 0 基线 **37.3%** → 阶段 2 **43.3%**（**真实增益 +6.0pp**）
- 辅助指标（阶段 0 → 2）：Top5 绝对收益均值 2.12% → 2.46%；排序 IC 0.148 → 0.180；最大回撤 −26.8% → −25.6%

### 3.2 模型级 walk-forward + λ 标定（`docs/backtest/model_walk_forward_40d.md`，2026-09-12）

- 引擎 `app/engine/backtest_model.py`，命令 `python -m app.engine.backtest_model 1200`
- 样本：1,200 基金 × 决策日步长 20 = **13,440 条**；验证集 2,688 条（最新 20%，**2026-04-29 ~ 2026-07-09**）
- 前瞻：**40 交易日**
- 特征增益（A3，λ=0.5 标签）：

| 特征集 | 维度 | 高分组胜率 | 低分组胜率 | 差 | IC |
|---|---:|---:|---:|---:|---:|
| 含 `style_r2` | 19 | 36.4% | 36.0% | +0.4pp | −0.022 |
| 不含 `style_r2` | 18 | 36.9% | 35.5% | +1.4pp | −0.003 |

- λ 扫描（B）：

| λ | 高分组胜率 | 低分组胜率 | 差 | IC |
|---:|---:|---:|---:|---:|
| 0.3 | 35.9% | 36.5% | −0.7pp | −0.066 |
| 0.5 | 36.4% | 36.0% | +0.4pp | −0.022 |
| 0.7 | 37.3% | 35.1% | +2.2pp | +0.014 |
| **1.0** | 37.9% | 34.5% | **+3.3pp** | **+0.075** |

- 报告结论：0.3→1.0 **单调改善**，λ=1.0 最优 → 生产 `RISK_ADJ_DD_LAMBDA` **0.5 → 1.0**，标签版本 v1 → **v2**（`LABEL_VERSION = "risk_adj_40d_v2"`）
- 验证期性质：**单边下跌段**，验证集整体 40 日胜率仅 **~36%**，两模型 IC 均 ≈ 0（区分度整体失效）
- 报告自述的局限：λ=1.0 **是测试上界，>1.0 未测**；验证期单一

### 3.3 风格跟踪 walk-forward（`docs/backtest/walk_forward_40d_2026-09.md`，2026-09-13 重跑）

- 抽样 300 只基金，样本 **6,573 条**（T × 基金），前瞻 40 交易日，反推窗口 60 日
- 赚饯口径：**> 1%**（`domain.is_profit` / `PROFIT_THRESHOLD`，覆盖申赎成本，与生产结算可比）
- 整体 40 日赚钱胜率 **51.9%**，平均收益 3.10%（旧 >0% 名义口径为 62.8%）
- 按反推主线权重 `weight_1` 分层：Q1 58.7% / Q2 57.3% / Q3 53.4% / Q4 38.1%，**Q4−Q1 = −20.6%**，单调性：**否**
- 按反推拟合优度 `r2` 分层：Q1 37.5% / Q2 52.5% / Q3 58.2% / Q4 59.4%，**Q4−Q1 = +21.9%**，单调性：**是**
- 相关性（Pearson）：`weight_1 ~ fwd_ret` r=−0.0825 (p=2.06e−11)；`r2 ~ fwd_ret` r=+0.1102 (p=3.14e−19)
- 多元回归（控制动量）：`weight_1` coef=−0.00008 (p=0.3632 **不显著**)；`r2` coef=**+0.04526 (p=1.05e−13 显著)**；`momentum` coef=−0.11797 (p=0 显著负贡献)
- 报告自述的限制：静态季报 RBSA 对照列因 `fund_features` 无历史快照不可得，未纳入——**这正是 2.0 要补多期持仓的动因**

### 3.4 遗传算法的事故与噪声（`app/engine/ga.py` 自述）

- 适应度定义：`fitness = profit_rate × 2 + 期望绝对收益%`，**即验收主标尺本身**
- 单次 fast 回测 `profit_rate` 噪声 **≈ ±8pp**（fitness ≈ ±16）
- **GA 历史上曾把线上参数推到 −28.7%**（`momentum_guard_pct` 被往负方向推坏，此后该基因被冻结）

### 3.5 1.x 测试与静态检查基线（`1.x-final`）

- `pytest -q`：**912 passed, 0 failed**（95.9s）
- `ruff check .`：**37 errors**（26 可自动修）
- `mypy app`：**18 errors**（12 文件 / 54 源文件）

三者均**未修复**——它们是 1.x 的既有状态。记录在此作为 2.0 改动的对比基线：2.0 不应新增错误，且被删除模块的既有错误应随之消失。

顺带发现一处潜在运行时缺陷：`app/engine/monitor.py:974` 引用了未定义名 `get_sector_pct_map`（ruff `F821`）。该模块在 ticket 22 中删除，故不修；但这说明这条赛道优势判定路径**要么从未被执行过、要么一旦执行就抛 `NameError`**——是 1.x 「代码路径没有被测试覆盖到」的一个直接证据。

## 4. 归档时发现的两处证据与共识文档不一致

> 以下两处是实施 ticket 01（登记基线数字）时核对原始报告发现的。**已回填到 `docs/2.0-consensus.md`**，此处留档原始证据链。

### 4.1 λ：不存在"标定建议 0.7"这回事

`docs/2.0-consensus.md` 原文记「λ 三方冲突：生产 1.0 / 标定报告建议 0.7 / 2.0 文档 1.5~2.0」。

核对结果：**0.7 只是 λ 扫描表里的一个中间行，不是建议值**。标定报告的结论是 **λ=1.0 最优**，且生产**已经**据此从 0.5 改到 1.0（标签 v1→v2）。`data/calibration_report_40d.md` 全文未讨论 λ。

因此真实情况是**两方**，且方向相反的性质不同：

| 来源 | λ | 证据强度 |
|---|---:|---|
| 生产现值 + 标定报告 | **1.0** | 有扫描证据，但**验证期是单边下跌段**，且 1.0 是**测试上界**（>1.0 未测） |
| 2.0 文档 | 1.5~2.0 | **无任何证据**，是沿同方向的未验证外推 |

**对 2.0 的结论**：ticket 09 的 λ 初值应取 **1.0（与生产一致）**，而非文档的 1.5~2.0。理由有二：一是 1.0 是唯一有标定证据的值；二是 λ 变了标签就变、模型就变，**会破坏与 1.x 参照曲线的可比性**，而这条参照曲线是 Q12 明确要保留的哨兵。文档的 1.5~2.0 记为待验证假设，进标定报告。

### 4.2 反推拟合优度 `r2` 有显著预测力，而它将被删除

共识文档记「style tracking 被自家回测否决」，引用的证据是 **−20.6% 与单调性为否**。但读原始报告：这两条说的是 **`weight_1`（反推权重）**，用于**分组**。而同一个报告里 **`r2`（反推拟合优度）** 的证据是**相反方向**：

- 分层 Q4−Q1 = **+21.9%**，**单调递增**
- 多元回归（已控制动量）coef = **+0.04526, p = 1.05e−13**，报告明确标注"独立正贡献"
- Pearson r = +0.1102, p = 3.14e−19

也就是说：

| 用途 | 证据 | 结论 |
|---|---|---|
| 反推**权重**做**分组/同类** | −20.6%，非单调 | **否决** → Q3/Q19 用 RBSA 持仓聚合分组 ✓ 一致 |
| 反推**拟合优度 r2** 做**特征** | +0.045, p<1e−13；模型级未复现（含/不含差异在噪声内） | **单因子证据显著，模型级证据不支持** |

ticket 22 会删除 `app/features/style_solve.py` 与 `fund_style_track`，**连带删掉 `r2` 这个特征**。这是一个**需要显式决定的取舍**，不能静默随删除一起消失：

- 支持删除：模型级（`backtest_model` A3）**未复现**增益，含/不含差异（+0.4pp vs +1.4pp，IC −0.022 vs −0.003）在 ±8pp 噪声内；且 `style_solve` 的计算链（60 日净值回归）在 2.0 里没有其他消费者
- 支持保留：单因子全样本证据很强（p=1e−13、Q4−Q1 +21.9% 单调），且 2.0 的新特征集本来就包含"持仓聚合"类特征——`r2` 是**反推一致性**，与 RBSA 是不同信息
- 折中：`r2` 可作为候选特征进 2.0 特征集（ticket 08），由 ticket 19 的影子闸门用自己的证据决定去留；但**必须先实现**，否则删除后无法再评估

**当前处置**：先记为未决事项，不在 ticket 22 里静默删除；`style_solve` 的删除推迟到该决定做出之后。

## 6. 为什么只能靠备份而不能靠 git

`data/qfund.db` 是 **871 MB 的二进制文件**，从未进入版本控制（也不该进入）。因此：

- 代码 → `git checkout 1.x-final` 可回滚
- 数据 → **只有备份**。`DROP TABLE`、`DELETE`、`VACUUM` 都是不可逆的

这就是 ticket 01 被列为**唯一不可延后**工单的原因：所有删除动作都必须排在备份之后。
